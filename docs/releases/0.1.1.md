# bited 0.1.1

Patch release of the Rust Varint + ZigZag library and companion Lean 4 package.
Public API signatures, decoding policies, error precedence and consumption
contracts are unchanged.

- `decode_u64` inlines one- and two-byte successes into callers and delegates every
  other input, including every error, to the unchanged verified scan, kept out of
  line as a cold function. Lean proves `decode_u64_eq_scan`, so every existing
  refinement, totality, value and resource theorem carries over.
- Decode wrappers and ZigZag mappings are `#[inline]`.
- `scripts/check-decoder-inlining` inspects downstream machine code and fails if the
  public decoder is called out of line.

On the recorded Apple M5 comparison against 0.1.0 source, short-weighted u64
decoding (80% one-byte, 15% two-byte, 5% full-width) uses about 81% less CPU time
per value, one- and two-byte decoding about 55–60% less, and full-width decoding
about 17% less. Lengths three and four show no clear change. Encoding code is
unchanged. Results depend on distribution, host and whether the caller's compiler
inlines the fast path; `verification/performance/RESULTS.md` retains every dataset,
interval and limit. Runtime optimality is not a theorem.

Library object code is smaller because the fast path now lives in callers; complete
applications may grow slightly at each decode call site.
